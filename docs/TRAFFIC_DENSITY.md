# 仿真道路车流增密

2026-10-22：将共享地图场景的车流预算由 800 辆提高到 6000 辆（7.5 倍），单段道路由最多 4 辆提高到 16 辆，车辆生成间距由约 180 米改为 65 米。预算是整个场景上限，不代表每个视角同时可见 6000 辆。实际数量受道路长度与可行驶道路数量限制。

代码：`frontend/src/views/DigitalTwin/cityTraffic.ts`。`CITY_TRAFFIC_BUDGET` 控制总量，`MAX_VEHICLES_PER_ROAD` 与 `VEHICLE_SPACING` 控制单段密度。沿用哈希排序以避免只取 OSM 文件开头的道路，不在步行道、自行车道或 service 道路生成车辆。保留行驶方向、车道偏移、道路/桥梁高度、车流开关。

所有车辆车身/车顶仍各用一个 InstancedMesh，增加车辆不增加独立网格数量；矩阵缓冲改用 DynamicDrawUsage。资源由原场景释放流程持有，未添加纹理、定时器或事件监听。

## 验证

- 前端 61 项测试通过（新增 3 项），类型检查和生产构建成功，构建仍有既有第三方注释/大包警告。
- 使用杭州主城区真实道路数据，测试得到 6000 辆，验证两车道、循环运动、桥梁高度、确定性分布及总量上限。
- Windows 本机内置浏览器，真实 Vue/Three.js 场景组件样例；画布 CSS 917×824，绘制缓冲 1146×1030，DPR 1.25，WebGL、暮色、同一初始钱塘江视角。预热后读场景最近 180 帧间隔统计：修改前 p50/p95 约 6.3/6.7ms，修改后约 6.2/6.5ms；绘制调用均 291，三角形 2233693→2358493。差值处于测量波动，不宣称性能提升。
- 独立 Node CPU 更新微基准（同数据，预热 60 次后采样 300 次）：800 辆 p50/p95 约 0.199/0.529ms，6000 辆约 1.342/3.267ms。数量增加确有 CPU 成本；不是 GPU 计时或所有电脑的帧率保证。
- 浏览器开关关闭/开启均可用，关闭后调用数 289（少 2 次）。最新 warn/error 日志为空。截图保存在 `tmp/traffic-density/`。

本次未评估长期内存趋势或实机交通准确性；不是交通流量统计功能，也不改动 Java、任务、飞机或数据库。总览与数字孪生复用该场景，刷新页面即可加载新车流密度。
