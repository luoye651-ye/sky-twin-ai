# 自然语言调度第一版

2026-11-16修复：预览工具不再依赖模型严格记住查询顺序。缺本轮飞行器数据时经原MCP查询，缺待分配任务集合时刷新原任务查询；仍校验指定编号和当前待分配状态，不自动选择或扩大任务范围，真实查询失败即拒绝预览，不重试不确定POST。128项隔离回归通过，受管Agent已加载；本轮未发真实模型或进行真实账号业务写入。见`verification/t10-dispatch-prerequisites.json`。

## 使用

启动项目后登录 http://127.0.0.1:5173/agent-command ，进入自然语言助手，输入：

> 请为所有待分配的物流任务生成调度方案，先预览不要执行。

也可明确任务编号、任务类型、飞机范围及普通/优先/紧急等级。模型应先查任务和飞机，再调用Java预览。一次最多20项，超过范围或条件不明确应要求缩小/明确对象。每条问题独立，不支持“刚才那个”等跨问题指代。

方案卡从Java再次读取真实方案，展示推荐飞机、候选原因、预计余电、分配数与基线比较。人工点击确认、填写原因后才通过原Java接口分配。分配成功后前往任务管理执行仿真。失败或过期应重新生成；预览响应不确定时先在算法调度历史核对。

## 实现与权限

- agent/dispatch_tools.py：只允许固定Java任务GET和方案预览POST；保留当前请求用户身份，令牌不进入模型参数。查询缓存、任务编号白名单、1—20项、优先级1—3、一次问题最多一个预览；相同预览复用，POST失败/不确定不自动重试。
- agent/aircraft_agent.py：网页增加list_dispatch_tasks与preview_dispatch工具，真实机队经原MCP查询。网页图循环预算16步，原CLI范围不变。方案编号从工具执行记录输出，生成成功文案由程序固定，不相信模型声称“已起飞”。
- AgentConversation：继续负责对话和依据展示；AgentDispatchCard仅接受方案编号，通过useFleetDispatch读取/确认原Java方案，复用DispatchPlanResult和确认对话框，不渲染模型伪造的分配表。
- Java未改：预览/确认均需sky:operate；查询需sky:read。预览会写方案与审计，不占用飞机；确认使用原5分钟有效期、锁、航线版本、当前状态复查及事务分配。并非只读聊天，也不是实机飞控。
- 原有RAG来源指纹包含Agent代码；能力文档已同步，新增调度代码来源并重新构建14段本地索引，没有绕过新鲜度检查。
