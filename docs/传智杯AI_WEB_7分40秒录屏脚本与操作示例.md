## 一、录制主线与准备

主线：示例河道图片 → DeepSeek看图 → YOLO检测 → 人工复核产生事件 → Agent生成方案 → 人工确认分配 → 仿真侦察 → 人工提交后图 → 冻结归档。补充账号知识库、实际调用轨迹和本地检索对照。

不必录完五类业务。通勤、北斗报文、资源维修、离线批量巡逻、多机错峰放技术PDF或加长版。物流仅作已预演成功后的备用主线。

### 录前准备，通常不计入成片

1. 主系统使用 http://127.0.0.1:5173 ，先自行登录有read/operate权限的账号；资源维护才需要manage。服务未启动时按项目启动说明运行 `ruoyi/scripts/start.ps1`。登录页、验证码和配置不入镜。
2. 准备有权使用的 `巡检示例_发现前.jpg` 与不同内容的 `巡检示例_处置后.jpg`。两图PNG/JPEG、每张≤2MiB、单边≤4096、总像素≤1200万。无实地前后照片时明确标为仿真示例，不能仅改文件名冒充处置结果。
3. 准备一架电量充足的空闲非eVTOL无人机、两个不同且启用的站点。先试过整条侦察航线，确认资源、电量、航程、空域与其他任务无冲突。不要为了录制停用既有规则或别人的任务。
4. 任务管理→创建仿真任务。示例名称 `传智杯演示-河道环境巡检-01`，类型环境监测，起终点选本机已验证站点，载荷0kg，速度10m/s，高度60m，原因 `传智杯演示：建立示例影像关联巡检，不发送实机指令`。点创建任务→该行分配飞行器→选空闲机并填原因→确认分配飞行器→执行仿真→填原因→确认执行仿真。等服务端显示执行中或已完成，记下真实编号。
5. 准备知识文件 [录屏示例巡检规程.md](demo/录屏示例巡检规程.md)。先试过索引和真实问答，正式录制只上传一次所需版本，不重复堆积文档。
6. 在便签记录原巡检任务、分析、发现、事件、应急任务、方案、归档报告、AI运行的真实编号。正文 `〈编号〉` 都必须替换；资源名称以本机下拉框为准，不编造固定ID。
7. 示例位置可先尝试代码表单默认经纬度120.190000、30.215000；这是人为声明的演示坐标，并非从图片识别，只有完整预演通过才采用。若不通过，换用已验证的场内演示位置与站点，并保持本条链一致。
8. 录制分辨率1920×1080；保留可读字号。允许剪掉等待，但字幕注明“省略模型等待”或“仿真过程节选”，保持同一编号的前后状态。真实AI调用由用户在页面授权后执行；5180合成样例不能冒充真实模型效果。

## 二、逐段成片脚本

### 01｜00:00–00:25｜项目价值，25秒

画面：项目名 → 运行总览。

话术：
> 大家好，我们的作品是SkyTwin AI，面向园区与河道巡检的低空任务协同Web平台。巡检中的图片、异常、派机和处置记录往往分散，我们把它们串成可追溯的业务流程。下面通过一条漂浮物示例，演示AI如何辅助发现问题、生成建议，并由人确认执行。

### 02｜00:25–00:45｜三维态势，20秒

画面：数字孪生，短暂切换视角/定位资源。

话术：
> 三维地图展示飞机、站点和任务态势，页面从Java业务服务读取状态。当前飞行采用本地仿真。接下来展示的示例影像也会明确标注来源，避免把仿真过程误认为实机航拍。

### 03｜00:45–01:30｜DeepSeek看图与追问，45秒

画面：上传同一张前图，发送首问与一次追问，展示返回。

话术：
> 首先上传示例图片，请DeepSeek描述疑似漂浮物的位置和不确定性，再围绕需要复核的区域追问。这里展示的是模型对图片的候选观察；它不会自动确认业务异常，也不会直接派机。图片理解帮助操作员缩小检查范围，最终判断仍由人工完成。

### 04｜01:30–02:25｜YOLO检测、图证与人工复核，55秒

画面：上传同图→YOLO结果→提交发现→确认事件。

话术：
> 随后进入上传检测。YOLO提供目标框、标签和置信度，操作员可以排除误检或改用人工框。系统分别保存原始预测与人工标注，并关联图片哈希、巡检任务、时间和声明位置。提交发现后，还需要填写复核原因和等级，确认后才生成业务事件，模型置信度也不等于整体识别准确率。

### 05｜02:25–03:20｜侦察任务、工具调用与调度预览，55秒

画面：同一发现创建侦察任务→关闭看图模式→文字请求方案→候选与原因/航线。

话术：
> 对这条已确认事件，先创建经过事件上空的应急侦察任务，再请Agent为这个真实任务编号生成调度预览。Agent通过受限工具查询业务数据，Java服务计算可行的资源匹配。方案卡展示推荐飞行器、预计余电和候选原因，可以查看航线；此时只是预览，任务尚未执行。

### 06｜03:20–04:05｜确认分配与仿真执行，45秒

画面：确认批量派机→提交原因→执行应急侦察→地图→服务端完成。

话术：
> 审查方案后，我填写派机原因并确认分配，再单独执行侦察仿真。确认和起飞都要重新检查资源与业务约束。地图展示服务端推送的位置变化，是否完成以任务状态和保存的轨迹为准。这里的任务是空中侦察，现实中的清理工作仍需另行组织。

### 07｜04:05–04:45｜后图、结案与报告，40秒

画面：同一发现提交后图→结案→巡检报告→追溯。

话术：
> 最新侦察完成后，人工填写处置说明并上传后图。服务端还会核对事件上空的仿真轨迹，再完成结案与报告归档。报告串起发现、事件、侦察任务、前后图片和操作记录，方便复查。本次使用仿真处置示例，不代表现实河道已经完成清理。

### 08｜04:45–05:40｜领域知识管理与RAG，55秒

画面：领域知识库上传→ready→本地检索→真实分析→展开引用。

话术：
> 业务规则可以通过账号自己的知识库管理。我导入一份录屏示例巡检规程，等待本地解析和索引，再询问提交发现前要核对什么。真实分析会结合检索证据生成回答，引用可以展开查看原文和版本。这里应核对图片来源、采集时间和声明坐标；资料不足时，也应保留未知，便于人工判断。

### 09｜05:40–06:30｜调用轨迹与检查点，50秒

画面：同一真实运行→模型/工具调用→Token→版本/检索记录→刷新后重选。

话术：
> AI工作台保存运行记录、成功检查点和实际调用轨迹。我们可以看到模型与工具是否成功、耗时和已上报的Token，用这些记录排查失败。刷新后仍能查询持久化的运行；遇到中断可按规则从成功检查点恢复。没有配置单价时，费用显示未知；预览响应不确定则先核对Java历史，不能盲目重复写入。

### 10｜06:30–07:05｜本地检索对照，35秒

画面：效果评测→语义vs混合排序→选2～3条→结果。

话术：
> 最后使用固定开发用例，对比语义检索和混合排序，查看命中、耗时与失败项，帮助定位知识检索的问题。这一组是在本地执行的检索回归，不是独立测试集上的模型回答准确率。视频中的数字只采用本次实际结果。

### 11｜07:05–07:40｜架构、创新与边界，35秒

画面：一页简洁架构与结束页。

话术：
> 前端使用Vue、TypeScript和Three.js，Java与MySQL统一维护业务状态，Python组织模型、检索和工具调用，若依复用登录与权限基础。作品的重点是把图片理解、图证复核、受控调度和结果追溯接入同一业务流程，同时保留可检查的AI运行记录。目前展示的是仿真运营，实机接入与领域识别效果仍需进一步验证。谢谢各位评委。

## 三、逐功能具体操作与示例

### A. 总览与三维地图（第01、02段）

1. 打开 http://127.0.0.1:5173/general ，停留展示当前任务、机队、告警；无需为了镜头新造告警。
2. 点击导航“数字孪生”，或打开 `/digital-twin`。
3. 在实际可见资源中选择演示无人机/定位入口，短暂调整视角，展示站点与飞机。
4. 目的：让评委先理解Web产品界面及任务与地图的关系。不要逐个读仪表数字，也不要用地图动画证明任务完成。

### B. DeepSeek直接看图（第03段）

1. Agent指挥 `/agent-command` → “自然语言助手”。
2. 勾选“图片＋自然语言（现有DeepSeek）” → 上传前图。
3. 确认来源可用后勾选允许图片、问题和最近三轮看图问答发送至DeepSeek的选项。
4. 在“向助手提问”中粘贴：`这张图里有哪些疑似漂浮物？请描述位置和不确定之处，不要推断拍摄地点，也不要确认业务事件。` → “发送问题”。
5. 结果返回后追问：`请进一步说明最需要人工复核的区域，以及仅凭这张图不能确定的信息。` → 发送。若明确有左下角目标，也可以问 `重点检查左下角，哪些判断还需要人工复核？`。
6. 镜头拍到图片、模型候选观察、不确定信息。实际检出数量以返回为准，不预写“一定检出3处”。
7. 目的：演示图片与多轮自然语言交互。此时还没有YOLO分析记录、业务发现或事件。

### C. YOLO检测与发现提交（第04段前半）

1. 环境发现 → “上传检测 / 发现与处置”，或 `/environment?mode=evidence`。普通 `/environment` 默认是离线影像巡逻，不能停在错误入口找表单。
2. 在“1 · 提交河道漂浮物发现”选录前执行中/已完成的环境巡检任务。
3. 填写：发现标题 `传智杯演示-河道漂浮物待复核`；影像来源 `仿真/示例图片`；经纬度填已预演通过的声明位置；采集时间填录制当天实际示例设定的含时区时间，如 `2026-11-16T14:00:00+08:00` 仅在相符时使用，不要把旧日期照抄到以后录制中。
4. “发现图片”选与看图相同的前图 → “分析这张图片”。
5. 展示分析编号、模型名、检出数与置信度。取消不认可的预测框；无检出或需补充时点“改用下方人工框”，按实际图中目标填写x/y/width/height（原图0～1比例），并写 `示例图中疑似漂浮物，人工标注待复核`。不要把默认框称作模型结果。
6. “提交发现，等待人工复核”。记录分析编号与发现编号。
7. 目的：把模型输出和人工判断保存成有来源的证据。

### D. 人工确认事件（第04段后半）

1. 在同一发现的“2 · 影像证据与人工复核”检查原图、关联巡检、坐标与哈希。
2. 人工确认等级选“中”。复核原因示例：`演示人工复核：示例图中存在疑似漂浮物，需要安排上空侦察；图像来源与坐标由演示人员声明。`
3. 点“确认异常并生成事件”，记录真实事件编号；需要时点“定位发现点”。
4. 目的：体现模型建议到业务事件之间有明确人工审核，且分析/发现/事件可以关联。

### E. 创建侦察与Agent预览（第05段）

1. 向下找到“3 · 应急侦察任务”。选已验证的两个不同出发/回收站。
2. 任务操作原因填 `传智杯演示：对本条已确认发现安排事件上空侦察，仅作仿真` → “创建应急侦察任务”。记录新任务编号，它与原巡检任务不同。
3. 回Agent指挥 → 自然语言助手，取消“图片＋自然语言”。
4. 输入：`请查询任务〈应急任务编号〉的状态，为这一个待分配任务生成调度方案，先预览，不要确认分配，不要执行。` → “发送问题”。
5. 等待实际工具进度和“Java方案”卡。点“候选与原因”，查看推荐资源/预计余电；点“查看航线：…”查看这一个任务的路线。
6. 目的：证明自然语言能够选择真实业务对象并请求受限工具，推荐结果由Java验收。单任务优化与基线相同很正常，不宣称本例体现大幅优化。
7. 若资源不足，先读未分配原因并处理测试资源；不要剪去失败后拼接别的任务。若方案过期或资源变化，重新预览并记录新方案号。

### F. 确认和执行（第06段）

1. 方案卡点“确认批量派机”。即使只有一个任务，按钮也叫这个名称。
2. 在“确认本批派机”填 `已检查本条事件侦察的推荐资源与路线，确认演示派机` → “提交派机”。核对已确认派机状态。
3. 回原发现详情，确认同一应急任务已分配。填任务操作原因 `执行本条事件的侦察仿真` → “执行应急侦察”。也可点“前往任务管理执行”后，在同一任务行点执行仿真、填原因、确认执行仿真；选其中一条路径即可。
4. 数字孪生展示这架飞机/本条任务，保留一小段移动画面；回详情等待最新应急任务服务端显示已完成。
5. 目的：拍清预览、分配、执行是不同动作。可在完成前顺带拍“等待最新侦察任务完成，暂不能结案”，只说明当前不能结案，不把按钮禁用夸大为本轮服务端拒绝测试。

### G. 后图与报告（第07段）

1. 回同一发现，确认最新应急侦察完成且没有其他活动尝试。
2. “4 · 提交处置后证据并归档”中填：`仿真演示：本条事件的上空侦察已完成，现提交处置后示例图说明归档流程。未实施现实河道清理，后图不作为实地清理证明。`
3. 上传不同内容的后图 → “提交证据并结案归档”。若被拒绝，按提示查最新任务和事件上空轨迹，不能改状态绕过。
4. 巡检报告 `/patrol-report` → “刷新环境归档” → 找本条标题 → “查看环境归档报告”。
5. 展示任务/事件关联、前后图与轨迹；“追溯发现与处置 →”可回原记录。需要导出时用报告实际提供的下载入口；此段不必另建报告中心草稿。
6. 目的：证明业务结果有完整证据链。普通飞行摘要与环境结案归档是不同报告，不要选错。

### H. 领域知识与RAG（第08段）

1. AI工作台 `/ai-workbench` → “领域知识库” → “新增 / 更新文档”选择新增文档 → 文件框选配套规程。
2. 等状态ready；需要时点“刷新索引状态”。若已提前导入，可以拍已有版本和状态，旁白改成“这里是已导入并建立索引的规程”，不重复假装首次上传。
3. “本地检索试验”输入 `录屏示例SOP要求提交发现前核对哪三项信息？` → “检索我的文档”。展示来源片段和版本。
4. “运行中心 / 轨迹” → 运行方式选“真实Agent分析（需授权）”；证据类型选“不指定，由工具查询明确范围”；问题填 `根据我的《录屏示例巡检规程》，提交发现前要核对哪三项信息？请引用原文，并说明模型是否可以直接确认事件。`。
5. 确认文件可外发后，勾选本次问题及知识证据发送给已配置外部模型 → “开始分析”。
6. 运行返回后展开建议正文中的引用，展示原文与版本。预期三项为图片来源、采集时间、用户声明的WGS84坐标；若回答或引用不支持，保留实际情况先修复准备，不读不存在的正确答案。
7. 目的：演示可管理的领域知识与有来源问答。个人导入文档在工作台使用，不默认普通助手已经读到它；只做本地检索时旁白改称“检索”，不能称作已完成生成回答。

### I. 真实轨迹与持久化（第09段）

1. 在运行列表选择H中新建的真实分析编号，不选“独立合成样例回放”。
2. 向下滚到“实际调用轨迹”，展示模型/工具状态、耗时及实际Token。纯知识问答若未调用Java工具，工具数为0也如实展示；业务工具的镜头采用E段实际进度。
3. 展开“执行版本与检索记录”，展示记录的版本/检索产物；有服务端证据时再展开证据快照。
4. 记下运行号后刷新页面，重新选择同一运行，显示历史仍保留；这仅证明持久化查询，不等于本次现场证明中断恢复。
