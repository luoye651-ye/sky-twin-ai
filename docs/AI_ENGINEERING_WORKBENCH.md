# AI工程工作台（2026-11-14验收）

本轮实现上一轮建议的七项首版，重点是“可恢复、可追踪、可对照、可独立演示”。入口 `/ai-workbench`，独立演示说明见 [deploy/README.md](../deploy/README.md)。

2026-11-15补充：原Agent自然语言对话现新增[DeepSeek直接看图](DEEPSEEK_IMAGE_CHAT.md)。下文工作台“读取既有YOLO分析记录”的模式仍按结构化证据处理，不与直接发送图片的视觉模式混淆。

## 数据流与组件边界

- `WorkbenchWorkspace`：路由组合、选择运行；`RunComposer`表达用户意图，`RunList`展示持久化历史，`RunInspector`展示结果和明确动作，`RunTimeline`展示调用记录。
- `KnowledgeWorkbench`管理账号自己的资料；`EvaluationWorkbench/EvaluationResults`分别选择评测和展示对照；`SpatialWorkbench/SpatialSelectionMap`负责框选与航线比较；`ImageEvidencePanel`显示原图、预测框及追问入口。
- Vue→已登录Agent接口→AI技术产物SQLite；业务读取或显式预览→原Java接口→原MySQL。SQLite不是第二套订单或任务状态机，确认状态必须回读Java。
- SQL位于 `ruoyi/backend/sql/agent_artifacts_sqlite_v*.sql`，只供Python的SQLite技术库使用，不加入MySQL业务迁移脚本。

## 明确边界

- 真实主系统沿用Java鉴权，读取需sky:read，知识上传、真实分析及模型评测需sky:operate。每账号24小时最多30次运行、60次模型调用尝试；工作台最多2个并发后台作业。
- 当前是固定业务流程的显式检查点实现，没有声称使用LangGraph原生checkpointer或分布式“恰好一次”。已完成读取可能是历史快照，最终业务操作由Java重新校验。
- 浏览器停止等待不代表Java预览已撤销；预览阶段不能假装取消成功。用户明确生成的方案仍可能过期，需要重新审查和生成。
- 连续追问每次重新查证所选图像记录，复用上一条问答帮助理解指代。它不等于无限长期记忆，也不自动证明两张图片来自同一地点或时间。
- 检索命中、工具调用/参数及词语断言不等于答案事实正确率。当前集合参与开发，不是独立保留测试集；未测数据不能填成效果提升百分比。
- 本轮开发与隔离验证不授权把本地资料实际发给外部模型；真实账号页面、真实模型新链路和公网交付必须另有实际证据才能写入简历。
