# AI水域巡逻：离线识别评测第一版

## 使用

登录大屏后进入主导航「环境发现」，或访问 `http://127.0.0.1:5173/environment`。旧 `/patrol-evaluation` 地址自动跳转并保留运行记录参数，不再单列「AI巡逻」导航。

1. 点击「启动仿真巡逻」，Java在1～132范围内均匀随机确定本次数量，从HAIDA test影像池无放回抽取相应图片，再进行真实推理。
2. 等待模型和数据校验、推理、图片生成完成；离开或刷新页面不会丢失后台运行记录。
3. 查看逐图列表，仅显示图片、检出数量和操作；可按有/无检出筛选，搜索文件名、翻页。
4. 点击「查看检测图」，在当前页面弹窗中查看预测图片，关闭按钮或Esc返回列表，不在列表下方展示图片详情。
5. 在运行记录中查看旧结果。同一记录的数量和图片固定，刷新/重开/请求重试不会重新抽样；只有新巡逻重新随机，数量偶尔相同也属正常。历史全量132张记录保留，不篡改成随机记录。

不需要重新人工标注，但评测依赖 HAIDA 已有标注。没有检出的图片也保留；不会为了演示人为补框。

2026-10-20按用户反馈精简为业务展示：不显示指标卡、查准率/召回率/mAP/GPU耗时、TP/FP/FN、标注对照、报告下载或巡逻示意动画；只保留必要巡逻操作、历史记录和检测列表。下文评测协议和分数属于后台可追溯记录，不是当前页面内容；没有为本次界面调整修改模型、数据或指标计算。

后续同日改动：移除弹窗可见标题和页面来源说明，检测图不再绘制HAIDA英文横幅。历史报告和原检测图不覆盖；使用 `ai/scripts/refresh_patrol_previews.py` 从原图及已存预测框生成 `preview/` 展示副本，鉴权图片接口优先返回该副本。新巡逻直接生成无横幅检测图。来源仍保留在模型清单/后台报告和此文档，去除展示文字不代表改成真实飞行或杭州影像。

随机协议为 `haida-patrol-random-v2`：计划数量在Java创建运行记录的同一事务内存入image_count；运行UUID作为抽样种子，图片列表保存为selected-images.txt，validator实际只读取这些图片，不是跑完132张再前端隐藏。报告保存抽样种子/影像池大小/协议，Java复核数量、去重、进度与完成计数。随机子集分数不代表完整132张测试集精度，不能拿各轮分数挑模型或声称效果提高。

随机版验收：28项Python测试、Java打包、Vue类型检查/构建、30项真实接口（含重启）和10项浏览器检查通过；本次两轮实际随机数量为51、30。新旧图片无标题/横幅、刷新保留样本、实际子集推理和幂等权限均有运行证据。历史全量测试分数仍仅作为旧协议记录，不能归到这两轮随机巡逻。

## 数据流与边界

Vue环境发现页 → 鉴权Java接口 → MySQL3307运行记录 → 固定参数Python计算进程 → 本地报告及图片 → Java验证并保存报告 → 精简列表及按需图片弹窗。

- Java 是运行状态唯一所有者；Python只计算，不写业务数据库。不增加新的HTTP服务或端口。
- 运行记录使用独立表 `st_patrol_eval`；迁移 `ruoyi/backend/sql/sky_twin_v9_patrol_eval.sql` 只增加表。
- 仿真巡逻调用已固定的离线影像识别流程；不创建真实飞行任务、不占用无人机、不触发环境事件或应急流程。原SVG示意动画已从页面移除。
- HAIDA是港区/沿海航拍离线数据，不是杭州实时河道画面，不能从这些图片自动推断杭州经纬度。
- 正常「环境发现」入口已替换为AI巡逻列表；原有带discoveryId的事件/归档追溯链接仍显示人工证据闭环，应急处置及已有数据保留。本次不自动把离线图片变成城市治理事件。
- 不承诺生产可用精度。瓶子类测试框只有12个，单类结论不稳定；数据集文件名前缀分组不等于已证实独立航次。

## 固定评测规则

| 项目 | 固定值 |
| --- | --- |
| 数据池 | HAIDA既定分组划分，test 132张/136真实框；每轮随机抽取1～132张 |
| 类别 | garbage、bottle |
| 推理输入 | 640，batch8，CUDA0，workers0 |
| 展示/逐图计数阈值 | conf ≥ 0.25 |
| TP匹配 | 同类，IoU ≥ 0.5；按置信度降序，一对一匹配 |
| Precision | TP/(TP+FP)，分母0显示「—」 |
| Recall | TP/(TP+FN)，分母0显示「—」 |
| mAP | Ultralytics8.3.221，置信度下限0.001，NMS IoU0.7，max_det300 |

mAP50使用IoU0.5；mAP50–95汇总IoU0.5至0.95。mAP不是固定conf0.25的查准率，不显示无意义的逐图mAP；目标检测没有可靠的背景真负例计数，本页不伪造一个分类式「准确率」。预测置信度也不等于识别准确率。

总体Precision/Recall由所有图片TP/FP/FN汇总，不取逐图百分比平均。标注只用于匹配评分和对照图，不输入检测器。无目标、无预测的图片两个比率均无定义，不记成100%。

## 模型发布和重现

必须先训练完成，再固定模型。脚本会校验训练完成记录、best.pt SHA256、数据manifest SHA256，拒绝发布中间检查点；不会用test分数选模型。

```powershell
# 根目录执行；等待续训完成后发布
.\ai\.venv\Scripts\python.exe ai\scripts\pin_patrol_model.py --run haida-demo-to100

# 数据和指标单元测试
.\ai\.venv\Scripts\python.exe -m unittest discover -s ai/scripts -p "test_*.py" -v

# 真Java/MySQL/CUDA/模型验收，保留本次完成的演示记录
.\ai\.venv\Scripts\python.exe ruoyi\scripts\verify-patrol.py --restart --ui
```

发布的权重按SHA保存于 `ai/weights/patrol/`，清单位于 `model.json`。每次任务都复核模型和数据哈希；发布变更发生于排队后则该任务失败，不静默换模型。已完成的历史报告和图片不随模型发布而覆盖。

模型未发布时按钮禁用并显示原因，不回退COCO或伪造结果。不要根据本页test结果反复修改阈值、挑模型，避免测试集泄漏。

## 权限、并发和故障

- GET 配置/记录/受保护图片：`sky:read`；POST 启动：`sky:operate`。只读账户不能通过直接API绕过按钮。
- 请求UUID幂等；数据库守卫行锁保证同一时刻仅一个活动任务。另一个点击返回现有任务，不重复起GPU进程。
- Python进程加本机文件锁，防止Java硬重启后的孤儿计算与新进程并发；锁冲突会明确失败，可在旧进程退出后重试。
- Java服务启动时将未完成记录标记失败，不冒充完成；报告只有完整132图、来源哈希、固定协议与计数/比率验证通过才写入。
- 子进程最多运行15分钟，停止时只终止本服务创建的计算进程，不影响用户训练。
- 图片类型与ID有白名单，只有报告内图片可读取；不暴露任意文件读取、任意权重路径或系统命令参数。
- 诊断日志 `ai/logs/patrol/<运行UUID>.log`；Java侧失败原因在本项目后端日志。

## 代码分工 / 本次学习点

- `shared/patrol.ts`：两端报告字段及前端类型；比率的null和0不同。
- `frontend/src/composables/usePatrolEvaluation.ts`：轮询、请求幂等、竞态和卸载清理。
- `frontend/src/components/patrol/`：控制区、巡逻示意、指标、列表、图片各负一责，路由视图只组合组件。
- `PatrolEvaluationController/Service.java`：权限、持久状态、并发保护和完成验收。
- `ai/scripts/patrol_eval.py`：固定协议推理及可追溯证据；`patrol_metrics.py`：框的一对一匹配。
