# 空域安全管控第一版

交付日期：2026-10-19（Asia/Shanghai）。入口为顶部“空域管控”或 `http://127.0.0.1:5173/airspace`；任务管理页也提供入口。

## 已实现闭环

配置矩形禁飞/限高区 → 检查已有任务的预计航线 → 显示违规位置与原因 → 起飞前按最新规则复核 → 保存检查/拒绝证据。平台任务、若依任务和物流订单最终均经过同一 Java `SkyService.taskAction(...,"start",...)`。

集群调度预览会把违规航线的原因加入候选排除列表；确认方案时再次检查当前区域规则，任何一项失败则整批派机回滚。预览通过不是放行凭证，实际起飞仍再次检查。

## 使用

1. 在任务管理或物流页创建任务，保持待分配或已分配状态。
2. 管理员进入空域管控，填写名称、WGS84矩形西/东经度、南/北纬度、高度和操作原因，选择是否启用及可选生效时间。
3. 选择任务及预计起飞时间（留空为服务器现在），点击“检查航线”。失败时显示区域、起飞/巡航/降落阶段、原因及预计进入时间；地图中红色区域为禁飞区、橙色为限高区、红线为所查任务的违规部分。
4. 从任务管理或物流页尝试执行违规任务，会被服务器拒绝；任务和飞行器状态不变、没有初始轨迹写入，检查记录保留。
5. 编辑区域停用、调整区域范围/高度/时间后，重新检查并起飞。同一条合法航线可正常执行。
6. 可在检查记录中回看当时的路线、区域规则版本、操作人和详细原因。记录中“通过”只表示检查通过，实际是否起飞以任务状态和任务审计为准。

本版不提供物理删除区域；停用后保留配置和操作审计。新安装使用 `migrate-sky.ps1`，已纳入新增的 `sky_twin_v4_airspace.sql`。本次已在专用3307库应用迁移，仅新增表。

## 明确规则

- 范围为WGS84矩形，不跨经度180°；西经度小于东经度、南纬度小于北纬度，每个方向跨度最多2度，最多500个区域。
- 禁飞区为水平矩形与 `[minAltitude,maxAltitude]` 高度区间形成的空间；边界及高度端点包含在禁飞范围中。
- 限高区允许高度等于上限，只拒绝严格超过上限的部分；其高度下限固定为0。
- 高度使用项目仿真原点相对高度（米）。无人机模型的220～340米视觉抬升不参与检查；没有DEM时不称为真实离地高度监管。
- 开始时间包含、结束时间不包含，即 `[startsAt,endsAt)`；任一留空表示该方向不限。已启用但处于生效时段外的区域在地图显示为灰色。
- 检查任务预计起飞至预计降落的完整路径。即使区域现在未生效，只要预计经过时已经生效，也会拒绝。
- 手动检查时间可选现在到未来30天；接口允许5秒提交延迟。所有时间使用本地部署的Asia/Shanghai墙钟约定。

## 计算与事务

`AirspaceEngine` 将现有仿真路径表示为三段：前10%时间垂直起飞、中间80%直线巡航、后10%垂直降落，与 `SkyService.tick` 的位置/高度插值一致。每段连续裁剪经度、纬度、高度和时间区间，求共同交集；不靠整数秒采样，因此狭窄区域不会因为落在两次采样之间而漏检。阶段交点归后一个阶段，最后降落端点包含在路径内。

区域保存和放行复查共同锁 `st_airspace_policy` 的单行规则版本，再读取当前区域。区域更新、版本递增和区域审计处于同一事务。任务及飞行器锁顺序保持原任务服务的顺序，首次通过后不能用旧网页结果跳过复查。

检查证据由独立 `REQUIRES_NEW` 事务保存到 `st_airspace_check`，因此外层起飞拒绝回滚时，拒绝证据仍在。记录表以任务ID和标题快照关联，刻意不建立任务行外键，避免独立事务等待外层已经锁住的任务行。证据包括路径、裁剪后的违规起止点/时间、当时规则版本、区域名以及原始区域边界/高度/生效时间。

放行检查通过记录也独立保留；如果后续载荷或其他写入失败导致业务回滚，该记录仍只表示“当时空域校验通过”，不代表任务已经执行。页面对此有明确说明。

新增表：`st_airspace_policy`、`st_airspace_zone`、`st_airspace_check`。不在旧FastAPI中维护第二套规则或任务状态。

## 接口与权限

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/sky/airspace/zones` | `sky:read` |
| POST | `/sky/airspace/zones` | `sky:manage` |
| PUT | `/sky/airspace/zones/{id}` | `sky:manage` |
| POST | `/sky/airspace/validate`，`{taskId,departureAt?}` | `sky:operate` |
| GET | `/sky/airspace/checks`，最近200条 | `sky:read` |
| GET | `/sky/airspace/checks/{id}` | `sky:read` |

区域配置与放行证据由Java保存。`/sky/snapshot`及SSE新增 `airspaceZones`，普通数字孪生页从同一快照渲染；管理工作区可手动刷新区域与记录，保存后同步刷新地图。前端共享类型位于 `shared/airspace.ts`。

## 第一版边界

区域是项目配置的仿真规则，不能冒充官方真实禁飞区或民航空域审批。检查基于名义仿真时长和预计路径，停机/调度阻塞造成的实际墙钟偏移不属于本轮实时监管保证。已执行任务遇到新区域时不自动改线或停止，本版只保证起飞前及集群确认时复核。

本文件初版未加入多航点绕行、地形/建筑避障、两机时空冲突预测或实机飞控。2026-10-19后续增量已完成持久化人工绕行航点，并统一预计耗时、仿真插值和地图线，详见 `WAYPOINT_ROUTES_V1.md`；当前下一步为冲突预测与改时/改线复查，自动寻路及建筑避障仍未实现。

可选学习点：为什么“拒绝起飞”的业务更新需要回滚，而“拒绝的证据”需要独立提交？可对照 `SkyService` → `AirspaceService` → `AirspaceRecords` 三个类理解。
