# 多航点航线与禁飞区人工绕行第一版

2026-10-19。入口：顶部“航线规划”或 `http://127.0.0.1:5173/route-planning`。任务页有链接，配送详情可直接进入关联任务的航线。

本版是人工规划+服务端验收+任务仿真，不是自动寻路、实机飞控、建筑/地形避障或双机避碰。已有定位终端模式仍与任务仿真互斥，不能用定位接近终点冒充任务完成。

## 使用

1. 创建配送订单/任务，在航线规划页选择对应任务。起终点由站点固定；巡航高度、名义速度沿用任务配置。
2. 点击“校验草稿”查看直线是否被禁飞区/限高区拦截。
3. 选择“点击地图添加航点”，单击巡航高度平面添加中间点。先在表中选中航点，再选择“点击地图移动选中航点”重新定位；也可修改经纬度、调整顺序、删除或清空。
4. 黄色是规划草稿；服务端校验后红线是违规段。输入规划原因，校验通过后点击“保存航线”。只预览不会改变任务路径。
5. 返回任务或配送页派机并执行。起飞时再次检查当前空域、资源、电量和截止时间；任务仿真及保存轨迹沿同一条服务端路线。
6. 已执行或结束的路线不可修改，可在航线页查看已保存版本，或从配送详情查看实际保存的轨迹。

拖动仍用于相机旋转，单击用于添加/移动。拾取平面不是楼顶或地形；选点不能当作建筑避障结果。切换任务/重新加载会丢弃未保存草稿。多人编辑冲突时服务端返回409，原草稿保留，由用户重新加载决定如何合并。

## 统一路线模型

`RouteEngine.Plan` 保存：路线版本、原始中间航点、完整带时间偏移的三维路径、水平航程、仿真时长、速度与巡航高度。

- 最多24个中间航点；经纬度有限且在WGS84范围内；相邻点至少5m；水平航程10m～20km；仿真时长最多600秒。
- 距离是各水平航段球面距离的总和，不含垂直起降距离。三维路径为起点垂直起飞 → 等高多航段巡航 → 终点垂直降落。
- 起飞/巡航/降落分别占总时长10%/80%/10%；巡航段按每段距离分配时间，而非按航点数量均分。
- 新建/新保存路线时长为 `max(20, ceil(水平航程 / (名义速度 × 10 × 0.8)))` 秒。10为演示时间倍率，不是真实飞行时间。
- 沿用原有简化电量模型：每仿真秒0.08个百分点，派机/起飞要求保留余量。模型不表示真实机型续航。
- 空域连续裁剪检查所有航段及其时间区间，不只检查航点是否落在区域中；包括起飞和降落。原来的空间含边界、限高允许等值、区域结束时间不包含等规则保留。

创建任务、保存路线、起飞校验、Java仿真与大屏折线均使用这份模型。Java每秒采样，跨过非整数秒的航点时额外保存精确拐点；否则把1Hz样本连接起来会切过拐角。地图动画也沿时间参数化的各航段插值，不沿两个快照之间的直线抄近路。任务状态和完成仍由Java事务决定。

轨迹 `recorded_time` 是落库时间，`progress × durationSeconds / 100` 可换算名义仿真偏移；额外拐点可能在同一秒落库，不是硬件实测采样。停机和调度延迟不计入名义飞行时间，本版不承诺真实墙钟下的动态空域安全。

## 持久化、互斥与复查

迁移 `ruoyi/backend/sql/sky_twin_v6_routes.sql` 新增：

- `st_task_route`：不可变路线版本及完整JSON快照，每任务/版本唯一，保存操作人与原因。
- `st_dispatch_route_snapshot`：生成调度方案时记住任务路线版本。确认时路线版本变化即拒绝，要求重新生成。

正常业务没有删除任务入口；测试清理临时任务/方案时，由限定外键级联清理对应路线/方案版本快照。迁移不改写已有任务、坐标或轨迹，已加入 `migrate-sky.ps1`。

新任务从v1开始冻结初始路线。已有无路线快照的旧任务显示虚拟v0，兼容原直线时长，不在迁移中补造历史路径。旧任务终止后站点可能已移动，因此虚拟v0不是历史飞行证据；历史实际以原 `st_track` 为准。旧任务第一次合法保存后才产生持久化版本。

编辑只允许created/assigned任务。服务端按任务 → 已分配飞行器 → 空域规则的顺序加锁，检查expectedRevision，保存新版本、更新任务时长及写审计在同一事务内完成。任一失败都不覆盖原路径与时长。

保存时重新检查当前禁飞/限高规则、订单截止时间；已分配任务还复用原约束函数检查机型、载重、座位、仿真电量与定位模式。未分配任务的飞行器能力留待派机及起飞检查，预览通过不等同已有可执行资源。临近截止时，保存/派机/起飞可能因服务器时间推进而拒绝。

保存尝试的空域检查证据仍使用独立事务。即使路线保存回滚，也能解释为何拒绝；通过检查的证据不代表后续保存一定成功，更不代表已起飞。旧记录包含完整当时路线与区域规则快照。

## API与前端分工

| API | 权限 | 用途 |
|---|---|---|
| GET `/sky/tasks/{id}/route` | sky:read | 当前路线、任务状态及版本列表 |
| GET `/sky/tasks/{id}/route/versions/{revision}` | sky:read | 已存历史版本 |
| POST `/sky/tasks/{id}/route/preview` | sky:operate | 只校验候选草稿 |
| PUT `/sky/tasks/{id}/route` | sky:operate | 重新验收并保存 |

预览/保存输入示例：

```json
{
  "expectedRevision": 1,
  "waypoints": [
    {"longitude": 120.19, "latitude": 30.225},
    {"longitude": 120.193, "latitude": 30.225}
  ],
  "reason": "人工绕开中部仿真禁飞区"
}
```

端点不由客户端修改，高度不在航点输入中。预览返回 `allowed`、空域违规段、资源/时限原因和新的航程/耗时；合法请求的200不代表allowed=true。

Vue按薄路由、`RoutePlanningWorkspace`组合容器、航点编辑/校验组件、`useRoutePlanning`请求与草稿逻辑拆分。Three.js只负责巡航平面选点、草稿/服务端路线渲染和动画，不决定路线是否安全或任务完成。

服务端验收包括：直线拒绝、人工绕行通过、时间/距离重算、版本不可变/并发冲突、旧调度方案失效、新区域保存前复查、时限/电量、权限、审计故障整体回滚、Java执行中重启恢复、所有保存轨迹点在同一时序路线以及精确拐点、配送确认与原数据保留。

浏览器使用真实Java接口与实际WebGL场景，无业务接口模拟，验收地图添加/移动/排序/删除、保存/刷新/历史与只读权限。截图 `verification/waypoint-route-map.png` 与 `verification/waypoint-route-editor.png` 来自临时仿真验收资源，不是实机记录。

已观察到MySQL JSON往返对时间偏移产生约2e-15秒的末位舍入。保存响应与存储回读的数值比较使用绝对1e-9容差，结构、顺序、版本、整数时长仍逐项核对；重启前后已存版本使用精确比较。不会以扩大容差掩盖路径变化。
