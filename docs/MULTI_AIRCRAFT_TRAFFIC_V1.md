# 多机冲突预测与错峰起飞第一版（仿真）

## 用途与操作

入口：大屏顶部「多机协同」，或 `http://127.0.0.1:5173/traffic`。航线规划页亦有入口。

1. 在任务管理手动分配飞行器，或先确认 Agent 指挥页的批量派机方案。
2. 保存需要的航点路线，再进入多机协同选择已分配任务（最多20项）。
3. 调整任务先后顺序，配置提前量5～300仿真秒、最大额外等待0～600秒。
4. 生成方案，检查每项等待时间、不可执行原因以及未额外错峰时的冲突；可以定位地图上的黄色冲突点。
5. 填写原因并「确认预约并自动起飞」。确认从**当前仿真时钟**重新计算提前量；如额外等待或资源变化则拒绝，需重新预览。
6. 在预约列表查看倒计时、执行或复核拦截。取消预约只释放时隙，任务仍为已分配；终止已起飞任务使用任务管理。

已预约任务不能改线，也不能提前手动执行。先取消预约才能重新规划。无可行时隙时整批不能确认，不会只预约部分任务。原有任务/物流/若依的直接执行入口也受相同多机起飞检查约束。

## 明确的演示规则

- 检查保存的完整路线：垂直起飞、所有巡航航段、降落，不使用无人机视觉抬升高度。
- 水平间隔100m，计算另加10m局部投影保护带；垂直间隔30m。两个方向同时进入阈值（包含边界）才算冲突，时间必须重叠。这些是**固定仿真参数，不是法定安全标准**。
- 对每对重叠时段的线性航段，解相对高度区间与水平距离二次不等式的交集；不是每秒采样找碰撞，能发现两个采样点之间的交叉。
- 水平距离使用局部WGS84近似，面向本项目城区航线；不宣称全球测地精度、极区/跨日期变更线支持或经认证的安全间隔。缓冲带也不代表已证明的定位误差模型。
- 障碍包括正在执行任务的**剩余**计划路径、已确认等待中的预约、同批次已经排入的任务；不把未确认方案当作占用。
- 已完成、取消、失败的任务立即释放飞行占用；不把停在站点的地面飞机继续作为空中障碍。场坪/起降容量与地面停机冲突未建模，不能据此宣称同一站点的实际起降操作安全。
- 按用户选择顺序逐秒搜索第一个可行时隙，不是全局最优，也不抢占执行中任务。顺序不是修改任务业务优先级。
- 预约阶段复核航线版本、当前分配、电量/运力/类型、定位终端互斥、预计起飞时刻的禁飞/限高及配送截止时间，等待时间计入截止时间。
- 到点使用实际服务端墙钟时间再次校验空域、资源和截止时间；不通过则预约变为 `blocked`、记录原因，任务仍为 `assigned`，不生成起飞轨迹。它不是自动忽略规则或自动改线。

## 仿真时间与事务

`st_traffic_clock`保存唯一逻辑tick。一个调度周期事务内：全部执行中任务各推进一步 → tick加1 → 按顺序处理到点预约。任何写入故障整周期回滚。Java停止、重启或周期执行变慢时，飞行进度、预约和时钟一起暂停/变慢，不按墙钟补飞，不依赖浏览器倒计时。

新建路线已有10倍速度仿真耗时约定，tick仍代表一秒**服务器仿真执行步**；不再把预约tick额外乘10。页面估计的墙钟抵达时间不承诺真实到达，暂停后起飞会按最新墙钟截止时间拒绝过期配送。

所有任务动作、路线保存、批量派机确认、预约确认/取消及仿真周期先锁时钟行，再按任务/飞行器/空域策略顺序加锁。冲突读取使用当前锁定读，避免外层事务已建立旧快照而漏掉刚起飞的其他任务。确认使用整批事务，末尾审计失败也不能留下部分预约。

`st_traffic_slot`不是第二套任务状态机：`reserved/running/blocked/...`只描述预约；飞行和订单仍由原`st_task`、`st_logistics_order`及`SkyService`负责。同一任务可取消后重新预约，当前slot更新，历史方案JSON保存当时全部安排。

## 数据与接口

新增幂等迁移：`ruoyi/backend/sql/sky_twin_v7_traffic.sql`，接入`migrate-sky.ps1`。新增clock、plan、slot、check四表，不回写旧任务、原轨迹或站点坐标。活动飞行加预约最多200项。

| 接口 | 权限 | 用途 |
|---|---|---|
| GET `/sky/traffic` | sky:read | 仿真tick、最近200预约、20方案和100检查摘要 |
| POST `/sky/traffic/plans` | sky:operate | 持久化预览，含任务/期望路线版本及提前量/最大延迟 |
| GET `/sky/traffic/plans/{id}` | sky:read | 读取方案及冻结的预测结果 |
| POST `/sky/traffic/plans/{id}/confirm` | sky:operate | 原子复查、整批预约，需要reason |
| POST `/sky/traffic/slots/{taskId}/cancel` | sky:operate | 取消等待中的预约，需要reason |
| GET `/sky/traffic/checks/{id}` | sky:read | 读取手动/成功自动起飞检查的证据快照 |

手动起飞冲突证据通过独立事务写入`st_traffic_check`，拒绝后仍可追溯路线、对方计划、阈值和tick。不设锁定任务外键，以免独立事务等待调用者自身的任务行锁。检查通过仅代表当时多机几何检查通过，**不等于外层起飞事务最终成功**。自动到点复核被拒绝的原因保存在slot与`traffic.blocked`审计；方案预测证据保留在plan中。终端定位不参与自动飞行占用预测，终端启用的资源仍禁止进入任务仿真。

## 前端数据流与职责

`Traffic`路由只组合`TrafficWorkspace`。`TrafficTaskPicker`接任务/选择/禁用状态并发出选择、排序事件；`TrafficPlanResult`展示方案，发出确认和定位事件；`TrafficReservations`展示预约，发出取消与读取历史事件。`useTrafficPlanning`管理请求、卸载失效保护、操作状态和3秒只读轮询。所有位置和起飞决定来自Java；页面不写任务状态、不推进服务端tick。

地图复用现有CityViewport和点标记，不增加另一套Three.js渲染器。冲突点属于历史候选路线，不是实测位置或运行中的碰撞告警。

## 复跑验收

在项目根目录运行，使用专用3307和本机项目服务；会短暂重启本项目Java，不改3306/6379。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ruoyi\scripts\verify-traffic-algorithm.ps1
python .\ruoyi\scripts\verify-traffic.py --restart --ui
cd frontend
npm run build
```

算法性质检查报告输出到控制台；真实HTTP/数据库验收报告为`ruoyi/logs/traffic-verification.json`，真实浏览器验收为`traffic-ui-verification.json`。脚本使用随机前缀临时资源、独立账号和限定任务/原因的故障触发器，结束清理本轮数据、审计、检查与触发器。完整验证结果以最新报告为准，不以文档或构建成功代替业务验收。

不包含实机碰撞避免、建筑/地形净空、风场/转弯半径、通信延迟/定位误差传播、未登记航空器、机载感知、自动空间寻路、执行中动态避让、空域审批、真实北斗接入、真实飞行安全认证。执行中新增禁飞区不会触发空中改线；已飞行任务按冻结路线继续，新的起飞被复核。所有调度/时隙仍是规则与优化算法，不是训练模型结果。
