# 架构与 AI 选型

浏览器通过 Java 读取唯一业务状态，通过 FastAPI Agent 理解问题、检索资料及调用受限工具。自然语言生成的调度建议先成为预览卡，再经用户确认和 Java 事务验收。业务状态与 AI 技术产物分开保存。

| 技术 | 选择理由 | 集成与优化 |
|---|---|---|
| Vue 3、Pinia、Three.js | 复用三维指挥底座与已有业务交互 | 按路由加载资源，使用业务编号联动对话和地图 |
| Spring Boot、MyBatis、MySQL | 集中管理任务状态与并发业务约束 | 权限、事务、幂等、方案有效期及资源复查 |
| DeepSeek、LangChain、受限工具 | 复用既有模型服务，理解意图并查询业务 | 工具白名单、参数校验、上下文限额、超时和失败反馈 |
| FastEmbed、BGE 中文向量 | 本地 CPU 中文规程检索，减少外部 Embedding 依赖 | 语义与关键词融合、来源、版本、删除和引用 |
| YOLOv8n | 给出框和置信度，支持人工排除误检与补框 | 模型/原图指纹与预测记录；与大模型图片观察分开 |
| SQLite、检查点及调用回调 | 保存可追踪 AI 运行 | 显式恢复、真实模型/工具用量和失败记录 |

技术创新集中在受控 Agent、确定性调度与事务确认的组合，以及图像、知识版本、业务编号和调用轨迹的关联。应用创新集中在低空巡检从影像到报告的证据链。属于系统集成和工程实现，不宣称首创基础模型或实机能力。

具体说明见 `AI_WORKFLOW_V2.md`、`AI_ENGINEERING_WORKBENCH.md`、`DEEPSEEK_IMAGE_CHAT.md` 与现有验证记录。历史回归检查、真实模型连接验证、离线检测准确率和现场效果使用各自的评价范围。
