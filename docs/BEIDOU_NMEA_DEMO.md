# 北斗 NMEA 定位接入仿真演示

日期：2026-10-23。入口：`http://127.0.0.1:5173/positioning`，即“定位回放”。

现已补齐北斗 NMEA GGA 的软件协议适配演示，不是北斗硬件接收。此前已有 JSON 定位上报、Java 校验、地图和轨迹回放；本次在同一条链路前增加报文生成、服务端校验和解码，不建立第二套任务或定位状态。

## 直接演示

已在真实业务系统新建并保留独立资源“北斗协议演示机（仿真）”，型号 `BDS-NMEA-DEMO`，绑定终端 `BDS-DEMO-01`“北斗NMEA仿真终端”。初始位置为杭州 120.190000、30.215000。本次验收结束后已停用终端，飞机空闲；原四架飞机未被本次演示启用定位、派机或改坐标。

1. 登录并在“当前终端”选择“北斗NMEA仿真终端 · 北斗协议演示机（仿真）”。不要把已有 C-01 终端当成本次演示终端。
2. 点击“启用终端定位”，再点“北斗样例单次上报”。新面板会显示原始 GB/GGA 报文、UTC 日期、Java 解析结果及持久化回执。
3. 点击“开始北斗连续演示”，等待约 10～20 秒后点“暂停北斗演示”。点击“定位当前飞行器”可定位地图。每次上报响应后等 1 秒继续，位置由局部仿真轨迹产生。
4. 点击“模拟北斗失锁”，查看“无有效定位”拒绝回执；点击“模拟校验错误”，查看 Java 的校验和不匹配提示。错误点不成为最新有效位置。之后可点单次上报恢复。
5. 点“最近一小时”，播放、暂停或拖动历史轨迹。只播放有效位置，跨会话或超过 5 秒缺测不连线。再次演示前先生成新点；旧历史不在最近一小时时，需选对应时间窗。
6. 退出回放并点击“停用定位，恢复任务仿真”。只暂停或关闭页面不等于停用，启用期间飞机被排除在任务派机之外。

“查看报文样例”只生成本地预览，不上报、不写业务。真正的上报按钮每次生成当前 UTC 的新报文，不能把旧样例重新标成当前采样。

## 本次实现

- `frontend/src/utils/beidouDemo.ts`：将仿真坐标转换为度分、UTC 时分秒，生成 GB/GGA 字符串及 XOR 校验和，处理度分舍入和 UTC 跨日。
- `BeidouDemoPanel.vue`：按钮、原始报文、服务端解析与回执展示；权限/发送状态通过 props 输入，按钮通过事件交给现有定位组合函数。
- `usePositioning.ts`：JSON 与 NMEA 共用会话、序号、轮询与连续发送定时器，避免两个模拟器同时争用同一终端。切换终端或离开页面即停止发送。重复请求使用服务端标准化后的坐标，避免 GGA 舍入带来的内容冲突。
- `NmeaGga.java`：服务端限制长度与字段，验证校验和，解析经纬度、UTC、质量码、卫星数、HDOP 和高度。GN 不被自动声称为北斗；本版支持 GB/GN/GP GGA 的限定子集，不支持任意厂商协议。
- `PositionController`：新增 `POST /sky/positioning/devices/{id}/nmea-samples`，沿用 `sky:operate`，调用原 `PositionService.ingest` 事务服务，继续执行会话隔离、幂等、采样新鲜度、乱序和突跳校验。

接口体：`sessionId`、`sequence`、`gga`、`utcDate`、`takeoffAltitudeMsl`。响应包含 `decoded`、`receipt`、`simulation=true`、`source=simulated_terminal`。客户端不能用一个 source 字段把数据变成实机北斗。

## 必须保留的边界

生成的 12 颗卫星、HDOP 0.9、质量码及起飞点 MSL 12 米都是演示设定，不是实测，也不能将 HDOP 0.9 写成定位误差 0.9 米。GB 字头本身不证明物理接收机或真实卫星参与。

GGA 不包含日期，必须显式提供 UTC 日期。本版处理到毫秒，不处理闰秒；没有日期或日期无效会被拒绝。支持带有效度分坐标的失锁包；坐标字段为空的无定位包不在此限定子集内。

GGA 的 MSL 高度不能直接当作相对起飞高度：`相对高度 = GGA MSL 高度 − 起飞点 MSL 基准`。例如演示 `252 − 12 = 240m`。真实接入需要实际接收机坐标基准、现场起飞点高程和误差验收，不能沿用虚构的 12 米基准。

轨迹库继续只保存标准化位置及有效/拒绝回执，不新增 SQL，不保存原始 NMEA 字符串、卫星数或 HDOP 的历史。这些质量字段仅在本次响应中展示。校验和等格式错误在解析阶段拒绝，不写入定位轨迹；已解析但失锁的报文写入原拒绝记录。

未接入串口、厂商 SDK、实机北斗信号、RTK 修正源或飞控。没有实际定位精度、授时精度、通信可靠性或适航验收结果。既有位置仍用于软件仿真，定位不会自动完成任务或订单。

## 验证与部署

2026-10-23：119 项原定位规则、33 项 NMEA/定位边界检查、67 项前端测试通过；大屏类型检查、生产构建和 Java 打包通过。Java 已按身份核实后单独重启部署；MySQL、Redis、Agent 和两个前端未重启。Windows 运行中 JAR 锁导致的首次打包失败已通过停止明确归属的项目 Java 进程后重建解决。

用户自行在内置浏览器登录后，使用真实 Java/MySQL 完成绑定、启用、单次、连续、暂停、失锁、错误校验、恢复、重复请求、地图和只读历史播放；没有读取/转移登录令牌或绕过验证码。58 条有效记录和 1 条失锁拒绝记录保留用于展示，校验错误未占用序号或新增定位记录；终端最终停用。真实协议面板截图为 `tmp/beidou-demo/live-nmea.png`。

构建仍有既有第三方注释及大包警告。软件协议演示通过不等于真实北斗硬件验证通过。

复跑：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ruoyi\scripts\verify-positioning-algorithm.ps1
```

在 `frontend` 目录运行前端测试、类型检查及构建。后续改 Java 后须重新打包并部署；Windows 中运行的 JAR 会被锁定，操作前须核实进程归属，不能为抢占端口停止其他程序。
