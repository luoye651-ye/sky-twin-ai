# SkyTwin：功能速查与录屏指南

更新：2026-11-15。用途：先照例子操作一遍，再按最后的7分20秒安排录视频。按当前路由、按钮和已有验证记录整理；本次没有登录执行这些业务，录前仍需本人预演。

一句话介绍：**在三维地图上管理低空任务，让AI辅助看图、查规则和生成调度方案，再由业务服务验收、操作者确认，最后追溯执行与报告。** 飞行为电脑仿真，尚未接实机。

## 1. 开始前准备

主系统：http://127.0.0.1:5173 。管理端：http://127.0.0.1:5174 。用自己的若依账号登录；看数据需read，提交/调度需operate，资源与容量维护需manage。

如服务未启动，在项目根目录运行：

```powershell
cd D:\cursor\project\sky-twin
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ruoyi/scripts/start.ps1
```

录前只准备这些：

- 一张有权使用的漂浮物示例图，PNG/JPEG≤2MiB；另备一张明确标注为仿真样例的处置后图。若无真实前后影像，不能声称发生过实地清理。
- 一个执行中或已完成的**环境监测任务**，用于关联发现图证；一架可用巡检无人机、两个合适的站点。充电/维修/故障、低电量、定位终端启用都会影响分配。
- 本文配套的[录屏示例巡检规程.md](demo/录屏示例巡检规程.md)，用于知识库导入。
- 先完成一条独立测试链，记下任务、分析、发现、事件、方案及报告的真实编号。下面的 `〈任务编号〉` 等是占位符，不可原样发送。

**三类图片流程要分清：** DeepSeek直接看图回答自然语言问题；YOLO输出框和置信度；人工提交并复核后才形成业务事件。它们可以使用同一张示例图，但不会自动互相创建记录。

## 3. 照着做一条主线：巡检异常处理

### A. 先看图：理解AI能回答什么

1. Agent指挥→自然语言助手，勾选图片模式，上传示例图并确认可发送给DeepSeek。
2. 输入：`这张图里有哪些疑似漂浮物？请描述位置和不确定之处。`
3. 继续问：`重点检查左下角，哪些判断还需要人工复核？`
4. 展示候选观察、不确定性、模型来源；点运行编号可看调用用量。

**这里还没有业务发现或事件。** 后面的YOLO和业务提交需要自己操作。

### B. 检测与复核：把观察变成可追溯记录

1. 若没有环境巡检，先在任务管理创建“环境监测”并分配、执行，等到执行中/已完成。
2. 环境发现→“上传检测 / 发现与处置”，传同一张图，点“分析这张图片”。
3. 检查预测框；误检不选、漏检可人工补框。填写标题、实际采集时间、示例影像来源及声明坐标，关联前面的巡检任务，提交发现。
4. 在“影像证据与人工复核”填写原因、等级，点“确认异常并生成事件”。

**看到的证据：分析编号 → 发现编号 → 事件编号。** 坐标由用户声明，不是AI从图中定位。

### C. 调度与执行：从建议到业务动作

1. 在该发现详情的“应急侦察”区域选出发/回收站，填写原因并创建侦察任务，记下新任务编号。
2. 回到自然语言助手，**关闭图片模式**，输入：

   > 请为任务〈刚创建的侦察任务编号〉生成调度方案，先预览不要执行。

3. 查看Java方案卡、推荐飞机和原因，可点“查看航线”。确认前必须是待分配任务；过期或资源变化就重新预览。
4. 明确确认分配并填写原因，再到任务管理对同一个任务执行仿真。看进度、地图与服务端状态，不能只凭动画宣布完成。

**注意两种入口的区别：** 普通助手可以按问题生成方案卡；AI工作台“真实Agent分析”阶段只读，建议完成后还要手动填写任务编号、点生成Java预览。

### D. 归档：展示结果有依据

1. 最新应急侦察完成后回到同一发现详情，填人工处置说明、传与原图不同的后图，点“提交证据并结案归档”。
2. 如按钮未开放，检查最新任务是否完成、事件上空轨迹是否满足条件；不能跳过验证。
3. 巡检报告查看该事件的归档、轨迹、前后图与审计。也可在业务运营→报告中心用发现编号创建草稿、编辑版本并导出。

完整编号链：**原巡检任务 → YOLO分析 → 发现 → 事件 → 应急侦察任务 → 方案 → 归档报告**。前后是不同阶段的任务，但都关联同一条事件；不要剪入其他任务的完成画面冒充本条结果。

## 4. 再试两个AI工程亮点

**知识与依据：** AI工作台→领域知识库→上传配套规程→等待ready→先本地检索“录屏示例SOP要求提交发现前核对哪三项信息”。要展示生成回答，在运行中心选择“真实Agent分析”、不指定记录、填同一问题并授权；结果应展开原文与版本。上传个人资料参与的是工作台账号知识库，不要默认原普通助手已接入这份私有资料。

**轨迹与对照：** 工作台选一条真实运行，展示模型/工具调用、耗时、Token。再到效果评测选择“本地检索：语义 vs 混合排序”，勾选2～3条用例运行；说明这是固定开发回归对照，并展示未通过项。它不调用外部模型，不能据此宣布“模型回答准确率提升”。

**恢复选拍：** 有失败/中断运行时，可在运行中心从成功检查点恢复；真实分析需重新授权未完成模型请求。不要为了镜头去强杀正式服务；没有自然中断记录时，可以只展开持久化检查点。预览结果不确定必须查Java历史，不能点恢复反复写入。

**必须讲到的重点：** 项目价值、图片理解、工具调用/调度、RAG引用、完整业务结果、可控性、实际验证与限制。七分钟内不必逐页点完所有功能。

## 6. 录制前最后检查

- 分辨率1920×1080，浏览器字号可读；登录、密钥和本地配置不要入镜。
- 先逐段预演，确认模型能返回、任务可执行、报告能打开；源码和隔离测试通过不等于这条真实网页操作已通过。
- 正式主线使用5173主系统。5180独立样例只作明确标注的备用，不能代替真实工具与模型调用。
- 准备好编号便签；可剪掉网络和飞行等待，保留同编号的前后状态，不能用其他记录拼成功。
- 模型等待时展示实际进度；失败就说明原因，不伪装成功。录屏不会由AI自动完成现实处置。
- 使用“示例影像、用户声明位置、仿真飞行、人工处置证据”等准确表述；不要说“杭州实时航拍、实机北斗、高精度自主清理”。
- 最终检查成片时长、声音、字幕、链接及当前功能版本。现有旧视频约6分55秒、1080p，规格合适，但本次未观看确认是否包含最新功能。
