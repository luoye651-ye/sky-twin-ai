# 定位数据接入与轨迹回放第一版（仿真验证）

日期：2026-10-19。入口：大屏顶部“定位回放”，或 `http://127.0.0.1:5173/positioning`。

本版没有连接北斗/GNSS硬件，没有真实卫星数量、定位精度或实机飞控数据。电脑生成的坐标明确标记为 `simulated_terminal`，不是实测北斗定位。WGS84只是接口的坐标约定，不证明定位来自北斗。

2026-10-23更新：现已补充GB/GGA报文生成与Java服务端解析的北斗协议仿真演示，复用本版持久化、地图和回放链路，详见[北斗NMEA演示说明](BEIDOU_NMEA_DEMO.md)。本文原始验收记录与“不含NMEA解析”的历史版本描述仅指2026-10-19第一版；真实硬件与定位精度仍未验证。

## 直接操作

1. 用有 `sky:manage` 权限的账号登录，输入终端编号（如 `PC-UAV-01`）、名称并选择未绑定飞行器，创建绑定。
2. 飞行器必须空闲，点击“启用终端定位”。此时尚无有效点，地图不会把原资源位置伪称为终端定位。
3. 点击“开始连续上报”。每次HTTP响应完成后等待1秒再上报；电脑在选定飞行器原位置附近生成局部环形轨迹，初始相对高度240m。已有有效点时从该点继续，避免人为瞬移。
4. 查看Java回执、经纬度、相对高度；点击“定位当前飞行器”把相机移到有效点附近。地图超出杭州模型范围的终端点不伪造场内布点。
5. 暂停后可以点击“模拟无定位”“模拟延迟60秒”“模拟位置突跳”“重试上一条”。异常有持久化拒绝回执，拒绝点不会成为当前有效位置。
6. 点击“最近一小时”或选择时间段加载历史，播放/暂停、拖动进度、调整1/5/10倍速。“退出回放”返回实时显示。
7. 用完点击“停用定位，恢复任务仿真”。只暂停上报或关闭页面不会解除互斥，终端会显示过期/离线，飞行器仍不参与任务派机，需显式停用。

终端编号与飞行器一对一绑定，本版绑定不可编辑或删除；不要把已有终端误绑到其他飞行器。没有权限的账号只能查询和回放。验收不会替用户启用现有四架飞行器，需用户自行选择。

## 数据流与职责

电脑模拟器 → 已鉴权HTTP接口 → `PositionService`事务校验与写入3307 → `SkyService`快照/SSE覆盖显示坐标 → Three.js地图。

- Java仍是唯一业务状态来源，没有在旧FastAPI维护第二套任务状态。
- 新表 `st_position_device` 保存不可变绑定、启用状态、会话及最新有效点指针；`st_position_sample` 保存接收/拒绝回执、采样时间与服务端接收时间。
- `st_aircraft`原任务仿真坐标不被定位上报覆盖。快照只在终端启用且有有效点时合并位置，并携带 `positionSource`、`positionState`、`positionDeviceId`、`positionSampledAt`。
- 终端数据只包含位置，不伪造电量、速度或精度。资源列表/地图中保留的电量与速度明确不是定位上报数据。
- 所有定位时间使用带时区ISO时间，数据库存UTC `DATETIME(3)`，页面显示本地时间；不与原任务的服务器本地时间字段混用。
- 高度为 `relative_to_takeoff`（相对起飞点米数），地图采用平面底座，不能用于真实地形净空判断。终端/回放高度不使用原无人机的可视化抬升策略。

## 服务端规则

- 经纬度范围分别为[-180,180]、[-90,90]，高度[-100,10000]m，数值必须有限。
- 采样时间必须明确时区、最多毫秒，存储年范围1000～9999；查询跨度最多7天。
- 拒绝采样时间落后服务端超过30秒或超前超过5秒的数据；设备时钟未同步时需先校时，不能伪装为新数据。
- 一个启用会话内，序号必须递增。相同会话/序号、相同内容重试返回原回执，不重复存储；不同内容返回409。
- 有效采样时间也必须严格递增。拒绝点不会移动最新有效点，但新序号仍被消费，防止后到的旧包覆盖状态。
- `fixValid=false`、时间乱序、序号乱序、位置突跳均保留拒绝原因。
- 简化突跳过滤：水平位移最多 `100m/s × 间隔 + 30m`，垂直位移最多 `30m/s × 间隔 + 10m`。这是演示用合理性阈值，不是定位精度模型，也不是适航安全证明；每会话首个有效点没有前点可比较。
- 有效采样年龄≤5秒为新鲜，>5秒为过期，>30秒为离线；仅有拒绝包到达不会把定位变新鲜。启用后未收到有效点显示等待，超过30秒显示离线。
- 停用后旧会话不能继续上报，重新启用轮换会话并清空当前有效点指针，旧记录保留。

### 与调度互斥

启用/停用与任务分配共用飞行器行锁。只有空闲飞行器能启用；启用后统一Java任务服务拒绝维护/移除及派机，优化器明确排除，旧调度方案确认时也复查。不能通过若依、平台订单或原任务入口绕过。

定位接近终点不会自动完成任务，不生成原 `st_track` 任务轨迹，也不改变订单送达状态。这是接入/回放演示模式，不是外部遥测驱动实机任务执行模式。禁飞/限高第一版仍检查规划任务路径，本轮没有新增实时越界告警或自动处置。

## 回放边界

- 查询采用开始包含、结束不包含的时间段，默认只返回已接收有效点，按ID游标明确分页（每页最多1000）。
- 页面最多加载5页/5000点，超过时明确警告并要求缩短时段，不把截断路径称为完整轨迹。
- 回放按照原采样时间排序，只在同会话、相邻间隔不超过5秒的有效点间线性插值；跨会话、缺测、模型外区间断线，不补造飞行段。
- 回放只是当前页面的影子位置，界面水印标记“历史回放”；不会调用上报接口，也不会覆盖实时快照或改变业务状态。其他页面仍显示实时位置。
- 实时页面轨迹显示最近100条回执中的当前会话有效点，完整指定时段通过历史查询查看。

## API

均在 `/sky/positioning` 下，沿用若依登录令牌。当前是本地已鉴权的演示HTTP接入，不是对公网开放的设备协议网关。

| 方法/路径 | 权限 | 用途 |
|---|---|---|
| GET `/devices` | sky:read | 终端与有效点/定位新鲜度 |
| POST `/devices` | sky:manage | `{id,name,aircraftId}` 绑定 |
| POST `/devices/{id}/mode` | sky:operate | `{enabled,reason}` 切换，返回sessionId |
| POST `/devices/{id}/samples` | sky:operate | 上报并返回持久化回执 |
| GET `/devices/{id}/recent` | sky:read | 最新100条接收/拒绝回执 |
| GET `/devices/{id}/samples?from=...&to=...&after=0&limit=1000&acceptedOnly=true` | sky:read | 时间范围及ID游标分页 |

上报示例（sessionId与时间需要替换为实际启用会话和当前时间）：

```json
{
  "sessionId": "从启用响应读取",
  "sequence": 0,
  "sampledAt": "2026-10-19T08:00:00.000+08:00",
  "longitude": 120.19,
  "latitude": 30.215,
  "altitude": 240,
  "fixValid": true
}
```

字段格式错误/权限/会话失效按错误响应处理。合法格式的上报也可能返回HTTP业务成功，但 `data.accepted=false`，须读取 `verdict`，不能把接口200等同于定位有效。来源由服务端固定，客户端传入 `source=real_beidou` 不会改变来源。

## 学习点与下一步

核心区分：采样时间与接收时间、幂等序号与会话隔离、原始回执与最新有效点、实时状态与只读回放。

用户尚未亲手复跑或解释上述规则，不标记为已掌握。可选小练习：连续上报后暂停，观察过期/离线，再解释为什么“收到无定位包”不能让坐标变新鲜。

后续真实硬件需要补实际协议适配（如串口/厂商SDK）、设备级鉴权、时间/高度基准转换及实机联调；不能只改界面来源标签。本版不含NMEA解析、RTK融合、真实定位误差评估、飞控指令、遥测驱动任务完成、自动避障或动态空域处置。
